# Safety

- Loopback bind only (`PINGCLI_BIND` is the explicit opt-in the container uses); the compose file publishes `127.0.0.1:7806` only (a test pins it).
- Host header must be a loopback name (or one in `LAB_ALLOWED_HOSTS`). Writes, and the GETs that start pingcli (`/api/stream`, `/api/version`), must be same-origin: a cross-site or same-site `Sec-Fetch-Site`, or a foreign `Origin`, is 403. `X-Forwarded-Host` (sent by the shared lab-proxy) replaces Host in that check only when it names a host on `LAB_ALLOWED_HOSTS`; any client can send the header, so it can never make an arbitrary origin same-origin.
- Netguard blocks every non-loopback outbound connection from the server process (fetch, socket, DNS, UDP) with a self-test, and a test runs all 14 commands in Mock and asserts zero attempts. Mock starts no child process at all (a test proves it with a marker binary).
- No free-form command ever runs. A caller sends only a key; the 14 allow-listed commands have fixed arguments; the lookup table has no prototype, so `__proto__`, `constructor` and other odd keys are 400, and a key that is not plain is never echoed. pingcli is started with `spawn(..., { shell: false })`; no `exec`, no shell string.
- Real (owner-run only; agents test it with stub binaries):
  - Settings: `PINGONE_ENVIRONMENT_ID` (a UUID), `PINGONE_REGION` (NA, EU, CA, AP/ASIA, AU, SG; anything else is refused), `PINGONE_CLIENT_ID`, `PINGONE_CLIENT_SECRET`, from the process environment or `~/Development/.env` (`STANDALONE_ENV`). Only those four keys are read from the file, and it is never loaded into the process environment.
  - The client secret is write-only: it goes only into `config.yaml` (mode 600) in a fresh private temp dir (mode 700, with `owner.pid`) that is also the child's HOME (pingcli's token store). A mode switch ends the Real session: no run of it spawns again (also when it is waiting for `auth login`), every child is killed and awaited, then the dir is removed. The same happens on exit. At start-up the lab sweeps stale `pingcli-lab-XXXXXX` dirs a crashed run left behind: only real directories owned by this user whose owner process is gone (or, without a pid file, that predate the process). In Docker it lives on a tmpfs `/tmp`.
  - The child gets a minimal environment (PATH, HOME, TMPDIR): no `PINGONE_*` or `PINGCLI_*` variable reaches it.
  - Every byte of output is scrubbed of the client secret and client id (raw, JSON-escaped, URL- and form-encoded, and the Basic header value base64(id:secret)) before it is sent, including a value split across chunks; the server never logs child output.
  - 15 s timeout (as in AI-DEMO2), 1 MiB output cap, one run at a time per workspace. Each child leads its own process group: timeout, cap, browser disconnect, Reset and mode switch kill the whole group, and a run ends at most 1 s after the child exits even if a grandchild holds its pipes. A caller that disconnects during `auth login` stops waiting at once; the login is killed when no caller is left.
  - `GET /api/version` in Real spawns once per session; parallel callers share it.
  - `agent-skills install` writes only into a throwaway `--output-dir` inside the private dir, removed after the run.
- Mock output uses only `.example` hosts, made-up UUIDs and names from the cast. `customer.config.json` sets four display strings and is git-ignored.
- No tenant, credential or customer identifier ships. The Docker image bakes pingcli 1.2.0 checked against a pinned sha256 and never a setting.
